# mora_bot —— Jellyfin 用户管理 Telegram Bot

mora_bot 是一个用 Go 编写的 **Jellyfin 用户管理 Telegram Bot**：让用户在 Telegram 里自助注册/绑定 Jellyfin 账号、用卡密续期、签到攒积分，管理员通过面板发卡、管用户、处理求剧工单，全程无需登录服务器。

## 功能矩阵

| 模块 | 功能                                                                            | 状态 |
| ---- | ------------------------------------------------------------------------------- | ---- |
| 账号 | 邀请码注册（克隆模板用户 Jellyfin 权限策略，重新注册即开启新订阅周期）；管理面板可「开注」免邀请码注册，并可限定开注名额（用完自动关闭） | ✅   |
| 账号 | 绑定 / 续期 / 改密（旧密码验证） / 忘记密码重置（安全码校验，每用户最多 2 次）；订阅已到期的账号需先续期才能绑定，但可直接 `/register` 重新开通（bot 创建的旧账号会被清理，用户自己绑定的账号绝不删除） | ✅   |
| 账号 | 自助解绑、自助注销（彻底删除 Jellyfin 账号）                                    | ✅   |
| 账号 | 订阅到期：到期前私聊提醒；到期自动停用 Jellyfin 账号（`EXPIRE_AUTO_DISABLE`），续期或加入白名单后自动恢复 | ✅   |
| 账号 | 管理员手动停用 / 解封（`/admin suspend`、用户卡片按钮）：Jellyfin 禁用 + 断开在线会话，与「到期停用」严格区分——巡检不会自动恢复，被停用者无法靠注册/绑定/续期自救，白名单提权也不会解封 | ✅   |
| 卡密 | 管理员批量生成邀请码 / 续期码（HMAC + XChaCha20-Poly1305 加密存储，明文不落库） | ✅   |
| 卡密 | 面板交互式发卡：邀请码选数量；续期码先选天数再选数量 | ✅   |
| 卡密 | 果果币兑换续期码 / 邀请码（/shop buy，价格运行时可在管理面板调整；白名单/永久账号不显示购买续期码入口）                                               | ✅   |
| 卡密 | 续期码核销（/redeem；白名单/永久账号会提示无需核销，且**不消耗卡密**）                                                                                           | ✅   |
| 积分 | 每日签到固定 5 果果币（无连签加成）+ 完整流水                                                                    | ✅   |
| 追剧 | 追剧中心：用户提交红果短剧求剧工单（/drama）                                                                    | ✅   |
| 管理 | 管理/用户面板分离：/start 仅用户面板，管理面板仅 /admin（tg_id 须与 env 一致）                                  | ✅   |
| 管理 | 管理面板：统计 / 发卡 / 调积分 / 查用户 / 卡密溯源 / 白名单 / 卡密定价 / Jellyfin 线路管理                      | ✅   |
| 白名单 | 白名单用户永久有效、不受规则约束、无需保号（面板添加/移除/查看；提权自动清除原到期时间，不再收到到期提醒） | ✅   |
| 媒体库 | 三层媒体库访问控制：模板基线（库访问+并发上限）→ 白名单单独覆盖 → 用户自选首页隐藏                              | ✅   |
| 线路 | 管理员维护 Jellyfin 线路；用户面板「查询线路」                                                                    | ✅   |

| 运维 | SQLite（glebarez pure-Go 无 CGO）+ WAL                                          | ✅   |

## 快速开始

```sh
cp .env.example .env    # 填写必填项
go mod tidy
go build ./...
go test ./...
go run ./cmd/mora
```

## Docker Compose 部署

项目内置 `Dockerfile` + `docker-compose.yml`，纯 Go + 无 CGO，构建为轻量静态二进制，容器内以非 root 用户运行。

```sh
# 1. 准备配置（已配置过 .env 可直接使用）
cp .env.example .env

# 2. 构建并启动（后台）
docker compose up -d --build

# 3. 查看日志
docker compose logs -f mora

# 4. 停止 / 重启 / 移除
docker compose down
docker compose restart
```

- `.env` 由 compose `env_file` 直接注入容器，**密钥不进入镜像**（见 `.dockerignore`）
- 数据库 `data/mora_bot.db` 通过 volume `./data:/app/data` 持久化，删容器不丢数据
- Telegram 为轮询模式，无对外端口，无需端口映射
- 应用收到 `SIGTERM` 后优雅退出（`main.go` 已用 `signal.NotifyContext` 处理）

> 提示：Windows 上需先启动 Docker Desktop（引擎运行中）再执行上述命令。

## 后台任务（自动）

| 任务 | 说明 | 配置开关 |
| ---- | ---- | -------- |
| 启动通知 | 进程启动后私聊所有管理员 | `BOT_STARTUP_NOTIFY_ADMINS=true` |
| 每日自动备份 | 每日在指定小时备份 SQLite（可选加密、可选推送到群），保留 N 份 | `BACKUP_DAILY_HOUR=3` / `BACKUP_KEEP_COUNT=14` / `BACKUP_ENCRYPT_KEY` / `BACKUP_GROUP_ID` |
| 到期提醒 | 每天扫描即将到期的用户并私聊提醒续费（白名单用户与无到期时间的用户不提醒） | `NOTIFY_BEFORE_DAYS=3`（0=关闭） |
| 到期停用 | 每天巡检 + **启动后补跑一次**：已到期账号自动停用（Jellyfin 禁用 + 断开在线会话 + 私聊通知），续期或加入白名单后自动恢复；动手前复核最新状态，刚续期的用户不会被误停用/误踢下线；未绑定 Jellyfin 的用户只更新订阅状态，不会收到「账号已暂停」这类不实提示。历史遗留的已到期账号会在下一次巡检时一并处理。巡检有动静时私聊汇报管理员，也可用面板「🔄 立即巡检」或 `/admin sweep` 手动触发 | `EXPIRE_AUTO_DISABLE=true`（false=只提醒不停用） |

## 管理面板

- `/admin` —— 打开管理面板（tg_id 必须与 env `ADMIN_TELEGRAM_IDS` 一致，否则提示「您不是管理员，无法使用」）
- `/admin stats` —— 全局统计
- `/admin gencode <数量> [invite|renewal] [天数]` —— 批量生成卡密（命令方式）
- `/admin addpoints <tg_id> <数量>` —— 调整果果币
- `/admin user <tg_id>` —— 查询用户（卡片带停用/解封按钮）
- `/admin suspend` —— 列出当前被管理员停用的账号（含理由）
- `/admin suspend <tg_id> [理由]` —— 手动停用账号（Jellyfin 禁用 + 断开在线会话）
- `/admin unsuspend <tg_id>` —— 解除停用
- `/admin sweep` —— 立即手动跑一次到期巡检（异步，跑完私聊汇报；与自动巡检互斥，撞上会提示）

**面板交互式发卡**（推荐，按钮向导）：
- 🎟 生成邀请码：点按钮 → 输入数量（1-200）→ 立刻生成
- ⏳ 生成续期码：点按钮 → 先输入天数（1-3650）→ 再输入数量（1-200）→ 生成

**管理面板其他能力（按钮向导）**：
- 🔍 查询卡密：输入邀请码或续期码 → 显示类型、状态（未使用/已使用/作废）、批次、使用者与使用时间
- 🪙 调整积分：输入 tg_id → 输入变动值（正加负减）
- 👤 查询用户：输入 tg_id → 显示用户名 / Jellyfin / 果果币 / 状态 / 白名单 / 到期（白名单用户到期列显示「无（白名单永久）」）；卡片底部带「🚫 停用账号」/「✅ 解除停用」按钮
- 🚫 停用/解封：输入 tg_id → 打开同一个用户卡片，用按钮停用（需输入理由，会一并告知用户）或解封
  - 停用 = Jellyfin 侧禁用 + 踢掉在线会话 + 本地 `status=inactive`；Jellyfin 同步失败则本地状态不变（不留「本地已停用、远端仍可登录」的假停用）
  - 与「到期停用」（`status=expired`）严格区分：巡检、续期、白名单提权都**不会**自动恢复 `inactive`，只有管理员解封才恢复
  - 被停用的用户无法靠 `/register`、`/bind`、`/redeem` 自救（这三处入口均拦截）
  - 被停用的用户即使「自助注销」也**不会解除停用**：本地档案保持 `inactive`（Jellyfin 账号照常删除），仍需管理员解封才能重新注册/绑定
  - 解封时若订阅仍到期，会回落到「到期停用」状态（Jellyfin 保持禁用），避免白送一段已过期的服务
  - bot 管理员账号不可被停用（面板不显示按钮，命令侧也会拒绝）：管理员身份来自 env，停用会连自己的 Jellyfin 账号一起禁用（自锁）
  - 停用名单：`/admin suspend`（不带参数）列出全部被停用账号与理由
- ✅ 白名单：添加（永久有效、不受规则约束、无需保号，并清除原到期时间）/ 移除（按 `NEW_ACCOUNT_VALID_DAYS` 补回到期时间，恢复受规则约束）/ 查看 / 📚 单独库与并发设置
- ⏰ 到期名单：列出「已到期停用」与「未停用（按到期日升序）」两类用户（含 tg、Jellyfin 用户名、到期日与剩余/已过期天数），便于催续费与核对停用是否准确
- 🔄 立即巡检：手动触发一次到期停用/恢复巡检（与每日定时、启动补跑共用同一互斥锁，不会并发跑）；跑完私聊汇报「停用 N 人 / 恢复 N 人 / 断开会话 N 个 / 失败 N 人」，失败会注明「本地状态未变，下次巡检自动重试」
- 🏷 卡密定价：设置邀请码 / 续期码所需积分数（运行时即时生效，商店同步）
- 🌐 线路管理：查看 / 添加 / 删除 Jellyfin 线路（用户面板「查询线路」可查）
- 📚 媒体库访问控制：三层模型（模板基线 / 白名单覆盖 / 用户自选隐藏，见下节）
- 📢 开注（免邀请码注册）：「🔓 注册与兑换」子面板切换开注状态，并支持**限定开注名额**
  - 🎯 设置开注名额：输入 N（>0）= 自动开启新一轮开注、名额 N 个；输入 0 = 不限名额
  - 每注册成功 1 人扣 1 个名额（原子扣减防超发）；名额用完**自动关闭开注**并私聊通知管理员
  - 若占用名额的那次注册随后失败（用户名被占用 / Jellyfin 不可达 / 落库失败），名额会**自动归还**；此时若开注是"因名额耗尽被系统自动关闭"的，会一并**自动恢复开启**并再次通知管理员，避免出现"名额还有剩余但入口已关"的死角。管理员手动关闭/改名额过的开注不会被自动打开
  - 「📢 开注：切换」重新开启时：上一轮名额未用尽则沿用剩余名额；已用尽则自动清零开启新一轮

## 媒体库访问控制（三层模型）

| 层 | 谁操作 | 存在哪 | 说明 |
| ---- | ------ | ------ | ---- |
| 1️⃣ 模板基线 | 管理员（📚 媒体库控制） | Jellyfin 模板用户 Policy | 全体普通用户的默认库访问（全部库/指定库）与并发会话上限 |
| 2️⃣ 白名单覆盖 | 管理员（✅ 白名单 → 📚 单独库/并发设置） | bot 本地 `users.jelly_lib_override`（JSON） | 白名单用户单独设置库访问与并发上限，设置后覆盖基线、立即生效；未设置覆盖的跟随基线 |
| 3️⃣ 用户自选隐藏 | 用户自己（📚 我的媒体库） | Jellyfin 该用户 Configuration（MyMediaExcludes） | 只能在"已被允许"的库范围内选择从客户端首页隐藏/显示；纯显示层，不影响搜索观看，无法给自己加权限 |

- **编辑模板基线**：📚 媒体库控制 → 🎬 编辑模板库访问 → 逐库 🟢/⚪ 切换 → 💾 保存（写入模板用户 Policy）
- **并发上限**：⏱ 设置并发上限（0=不限）。语义是同时在线会话/设备数，约等于同时播放路数
- **应用到全体用户**：🚀 按钮 → 回复「确认」→ 按当前基线批量覆盖所有本地绑定用户（白名单单独覆盖不受影响；Jellyfin 管理员账户自动跳过；异步执行，完成后汇报成功/跳过/失败数；Jellyfin 不可达时连续失败自动中止，可稍后重试）
- **注册即同步基线**：新注册/重新注册的账号在模板克隆之后按当前生效链（白名单覆盖/模板基线）再套用一次，不会带着过期的模板权限上线
- **移除白名单自动收回覆盖**：移除白名单时该用户的单独库/并发覆盖自动清空，并立即按模板基线重套（恢复受规则约束的访问）
- 白名单覆盖保存/清除时立即单独应用到该用户（清除 = 恢复跟随基线并重套）
- 所有批量/覆盖操作均写 `audit_logs`

## 卡密格式

- 邀请码：`mora-` + 20 位大写字母/数字（排除易混淆字符），如 `mora-A1B2C3D4E5F6G7H8J9K2`
- 续期码：`R<天数>-` + 20 位大写字母/数字。`R30-` 表示 30 天续期，如 `R30-A1B2C3D4E5F6G7H8J9K2`
- 卡密明文仅生成瞬间存在于内存；库中只存 HMAC 散列 + XChaCha20-Poly1305 密文


## 安全设计

- 卡密明文仅生成瞬间存在于内存；库中只存 HMAC 散列 + XChaCha20-Poly1305 密文
- 果果币变动一律在事务内（乐观锁 + 禁止负余额）
- 管理员动作全部写 `audit_logs`
- `SECURITY_PEPPER` 用于卡密派生密钥（≥32 字节，勿与备份密钥相同）
